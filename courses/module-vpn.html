1. Concepts Fondamentaux du Pare-feu

Un pare-feu contrôle le trafic réseau en appliquant des règles. Il constitue la première ligne de défense périmétrique d'un réseau.

A. Types de pare-feu

Type Fonctionnement Exemple
Stateless (sans état)Analyse chaque paquet individuellement selon IP/port. Rapide mais limité.ACL Cisco basique
Stateful (avec état)Suit les connexions. Autorise les réponses aux requêtes établies automatiquement.pfSense, iptables
Applicatif (L7)Inspecte le contenu applicatif (HTTP, DNS...). Peut détecter les menaces dans le payload.pfSense + Snort
NGFW (Next-Gen)L7 + IPS + filtrage URL + déchiffrement SSL + identification utilisateur.Fortinet, Palo Alto

B. Architecture DMZ

La DMZ (Zone DéMilitarisée) est un réseau intermédiaire entre Internet et le LAN interne. Les serveurs accessibles depuis Internet (web, mail) y sont placés.

Architecture 3 zones typique :
WAN (Internet) → Firewall → DMZ (Serveurs publics) → Firewall → LAN (Réseau interne)

Règle : Le LAN peut accéder à la DMZ et à Internet. La DMZ ne peut pas accéder au LAN. Internet ne peut pas accéder au LAN directement.

C. Politique de filtrage — Default Deny vs Default Allow

  • Default Deny (recommandé) : Tout est bloqué par défaut, on autorise explicitement ce qui est nécessaire. Principe du moindre privilège.
  • Default Allow : Tout est autorisé par défaut, on bloque ce qui est dangereux. Déconseillé en production.

2. pfSense — Présentation & Installation

pfSense est un pare-feu/routeur open-source basé sur FreeBSD. C'est la solution de référence pour les PME et les labos TSSR. Il intègre pare-feu, VPN, IDS/IPS, proxy, et bien plus.

A. Prérequis matériels

  • Minimum : CPU 64 bits, 1 Go RAM, 8 Go stockage, 2 cartes réseau minimum (WAN + LAN).
  • Recommandé labo : VM avec 2 Go RAM, 3 interfaces réseau (WAN + LAN + DMZ).
  • En production : Appliance dédiée (Netgate) ou serveur avec NIC Intel.

4. Règles de Filtrage pfSense

Les règles pfSense sont lues de haut en bas. La première règle correspondante s'applique. pfSense est Stateful : les réponses aux connexions établies sont automatiquement autorisées.

A. Logique des règles pfSense

Important : Sur pfSense, les règles de filtrage sont appliquées sur l'interface d'entrée (ingress), pas de sortie. Une règle sur l'interface LAN filtre le trafic qui vient du LAN.

B. Structure d'une règle pfSense

Champ Description Exemple
ActionPass / Block / RejectPass
InterfaceSur quelle interface s'applique la règleLAN
ProtocolTCP, UDP, ICMP, Any...TCP
SourceIP/réseau/alias sourceLAN net
DestinationIP/réseau/alias destinationany
Dest. PortPort ou plage de ports80, 443
LogActiver la journalisation✓

C. Règles typiques par zone

Firewall > Rules — Règles LAN (politique permissive standard)
# Règle 1 — Autoriser DNS depuis le LAN Action : Pass Interface : LAN Protocol : TCP/UDP Source : LAN net Destination : This Firewall (pfSense lui-même) Dest Port : 53 (DNS) Description : LAN peut résoudre DNS via pfSense # Règle 2 — Autoriser HTTP/HTTPS depuis le LAN Action : Pass Protocol : TCP Source : LAN net Destination : any Dest Port : 80, 443 Description : Navigation web # Règle 3 — Bloquer LAN vers DMZ (sauf services autorisés) Action : Block Source : LAN net Destination : DMZ net Description : Isoler la DMZ du LAN (Default Deny)
Firewall > Rules — Règles WAN (exposition services)
# Règle 1 — Bloquer tout depuis WAN (Default Deny implicite) # pfSense bloque tout depuis le WAN par défaut # Il faut explicitement autoriser ce qu'on veut exposer # Règle 2 — Autoriser HTTPS entrant vers serveur web en DMZ Action : Pass Interface : WAN Protocol : TCP Source : any Destination : WAN address (IP publique pfSense) Dest Port : 443 Description : HTTPS vers serveur web DMZ (avec NAT associé)

D. Aliases — Simplifier les règles

6. Concepts VPN

Un VPN (Virtual Private Network) crée un tunnel chiffré sur un réseau non sécurisé (Internet), permettant de communiquer comme sur un réseau privé.

A. Types de VPN

Type Usage Protocoles
Remote Access (Client-to-Site)Télétravailleur → Réseau entrepriseOpenVPN, WireGuard, L2TP/IPsec
Site-to-SiteSiège ↔ Agence (tunnel permanent)IPsec, OpenVPN, WireGuard
SSL/TLS VPNAccès web via navigateur (HTTPS)OpenVPN, SSL

B. Comparatif des protocoles VPN

Protocole Port Chiffrement Points forts
OpenVPN1194 UDP (ou 443 TCP)TLS + AES-256Très sécurisé, multiplateforme, passe les firewalls
IPsec (IKEv2)500/4500 UDPAES-256 + SHA-256Standard, natif Windows/iOS, excellent site-à-site
WireGuard51820 UDPChaCha20 + Poly1305Très rapide, code simple, moderne
L2TP/IPsec1701 UDP + 500/4500IPsec (AES)Natif Windows, mais plus lent (double encapsulation)
PPTP1723 TCPMPPE (faible)⚠️ Obsolète et non sécurisé — à ne jamais utiliser

C. Concepts clés de chiffrement VPN

  • Tunnel : Le flux chiffré qui encapsule les données originales dans un nouveau paquet IP.
  • PKI (Public Key Infrastructure) : Autorité de certification (CA) qui signe les certificats des clients et serveurs VPN.
  • Perfect Forward Secrecy (PFS) : Chaque session génère une clé unique. Si une clé est compromise, les autres sessions restent sécurisées.
  • Split Tunneling : Seul le trafic vers le réseau d'entreprise passe par le VPN. Le reste (YouTube, etc.) utilise la connexion locale directe.
  • Full Tunneling : Tout le trafic passe par le VPN (y compris Internet). Plus sécurisé mais plus lent.

7. OpenVPN sur pfSense (Remote Access)

OpenVPN est le VPN recommandé pour le télétravail sur pfSense. Il utilise des certificats TLS et peut passer les firewalls restrictifs via le port 443 TCP.

A. Création de la PKI (Autorité de Certification)

System > Cert. Manager > CAs > Add
# Étape 1 — Créer l'Autorité de Certification (CA) Method : Create an internal Certificate Authority Descriptive name: CA_VPN_MonEntreprise Key type : RSA 4096 bits Digest Algorithm: SHA512 Lifetime : 3650 jours (10 ans) Common Name : CA_VPN # Étape 2 — Créer le certificat du serveur VPN System > Cert. Manager > Certificates > Add Method : Create an internal Certificate Descriptive name: CERT_SERVEUR_VPN Certificate Authority: CA_VPN_MonEntreprise Key type : RSA 4096 bits Digest Algorithm: SHA512 Certificate Type: Server Certificate Common Name : vpn.monentreprise.fr

B. Configuration du serveur OpenVPN

VPN > OpenVPN > Servers > Add
# Paramètres généraux Server mode : Remote Access (SSL/TLS + User Auth) Protocol : UDP on IPv4 only Device mode : tun (layer 3) Interface : WAN Local port : 1194 # Cryptographie TLS Key : ✓ Générer automatiquement (protection DDoS) Peer Certificate Resolver: CA_VPN_MonEntreprise Server certificate: CERT_SERVEUR_VPN DH Parameters : 4096 bits Encryption algo : AES-256-GCM Auth digest : SHA512 Hardware Crypto : BSD cryptodev engine (si dispo) # Réseau tunnel IPv4 Tunnel Network : 10.8.0.0/24 # Réseau VPN dédié IPv4 Local Network : 192.168.1.0/24 # Réseau LAN à atteindre DNS Default Domain : monentreprise.local DNS Server 1 : 192.168.1.1 # DNS interne # Clients Dynamic IP : ✓ (IPs attribuées dynamiquement aux clients) Topology : subnet

C. Création des comptes utilisateurs VPN

System > User Manager > Add + Certificat client
# Créer un utilisateur System > User Manager > Add Username : jean.dupont Password : MotDePasseForT@2024! ✓ Click to create a user certificate Certificate name: CERT_jean.dupont # Générer la configuration client (.ovpn) VPN > OpenVPN > Client Export Remote Access Server : Serveur VPN (1194) Export type : Most Clients (fichier .ovpn tout-en-un) # Le fichier .ovpn contient : # - Adresse du serveur VPN # - Clé TLS, CA, certificat et clé privée client # - Configuration complète prête à l'emploi

Règles firewall à créer après installation OpenVPN :
1. Interface WAN → Autoriser UDP 1194 entrant vers pfSense
2. Interface OpenVPN → Autoriser le trafic des clients VPN vers le LAN
Sans ces règles, le tunnel monte mais le trafic est bloqué.

8. IPsec Site-à-Site

IPsec site-à-site crée un tunnel permanent entre deux sites (siège ↔ agence). Les deux pfSense s'authentifient mutuellement et chiffrent tout le trafic inter-sites.

A. Phases IPsec

Phase Nom Rôle
Phase 1 (IKE)ISAKMP SAAuthentification des deux pfSense et établissement d'un canal sécurisé de négociation
Phase 2 (ESP)IPsec SADéfinit les réseaux à faire transiter et les algorithmes de chiffrement du tunnel de données

B. Configuration Phase 1 (sur les deux pfSense)

VPN > IPsec > Tunnels > Phase 1
# SITE A (Siège) — IP WAN : 203.0.113.1 # SITE B (Agence) — IP WAN : 198.51.100.1 # ── Phase 1 sur le pfSense du Siège ───────────── Key Exchange : IKEv2 Internet Protocol: IPv4 Interface : WAN Remote Gateway : 198.51.100.1 # IP WAN de l'agence Description : IPsec vers Agence Paris Authentication : Mutual PSK (ou Certificats) Pre-Shared Key : [clé partagée complexe — identique des deux côtés] Encryption Algorithm : AES 256 bits Hash Algorithm : SHA256 DH Group : 14 (2048 bits) Lifetime : 28800 secondes (8h) # ── Phase 1 sur le pfSense de l'Agence ────────── # Configuration identique mais Remote Gateway = 203.0.113.1

C. Configuration Phase 2

VPN > IPsec > Tunnels > Phase 2
# Phase 2 sur le Siège Mode : Tunnel IPv4 Local Network : 192.168.1.0/24 # LAN du Siège Remote Network : 192.168.2.0/24 # LAN de l'Agence Protocol : ESP Encryption Algo : AES 256 bits Hash Algos : SHA256 PFS Key Group : 14 (2048 bits) — Perfect Forward Secrecy Lifetime : 3600 secondes (1h) # Phase 2 sur l'Agence # Local = 192.168.2.0/24 # Remote = 192.168.1.0/24 # (inversé par rapport au Siège)

D. Vérification du tunnel IPsec

Status > IPsec + Diagnostics
# Vérifier l'état du tunnel Status > IPsec # ✓ Phase 1 : Established # ✓ Phase 2 : Established # Depuis le Shell pfSense ipsec statusall ipsec status # Forcer la reconnexion si le tunnel est DOWN ipsec restart # Test de connectivité à travers le tunnel Diagnostics > Ping Source address : LAN du Siège (192.168.1.1) Destination : Un hôte de l'Agence (192.168.2.10)

Règles firewall IPsec : Créer les règles sur l'interface IPsec pour autoriser le trafic entre les deux sites. Sans règle sur l'interface IPsec, le tunnel monte mais tout le trafic est bloqué.

9. IDS/IPS — Snort & Suricata sur pfSense

pfSense peut être enrichi d'un IDS/IPS (Intrusion Detection/Prevention System) pour détecter et bloquer les attaques réseau en temps réel.

A. IDS vs IPS

Type Mode Action
IDS (Intrusion Detection)Passif — analyse une copie du traficAlerte uniquement, ne bloque pas
IPS (Intrusion Prevention)Inline — analyse le trafic en temps réelAlerte ET bloque automatiquement

🎯 Mémo Examen — Le plus important à retenir

A. Les pièges classiques pfSense

Règles sur l'interface d'entrée : Les règles pfSense filtrent le trafic entrant sur l'interface source, pas sortant.
Règles OpenVPN : Après création du serveur, il faut créer manuellement les règles sur les interfaces WAN et OpenVPN.
Règles IPsec : Idem — créer les règles sur l'interface IPsec après montée du tunnel.
Default Deny WAN : pfSense bloque tout le trafic entrant sur le WAN par défaut. C'est voulu.
DHCP + DNS : Toujours configurer le serveur DHCP pour pointer vers pfSense en tant que DNS.

B. Commandes de diagnostic rapide

D. Checklist déploiement pfSense

1. Changer le mot de passe admin par défaut
2. Configurer WAN (DHCP ou statique)
3. Configurer LAN (IP statique + DHCP server)
4. Vérifier les règles firewall par défaut (LAN → any = autorisé)
5. Configurer les Forwarders DNS (8.8.8.8, 1.1.1.1)
6. Activer les mises à jour automatiques
7. Configurer les backups automatiques (System > Backup)
8. Tester la connectivité depuis le LAN (ping, navigation)
9. Configurer les règles firewall restrictives selon le besoin
10. Activer Snort/Suricata sur le WAN
