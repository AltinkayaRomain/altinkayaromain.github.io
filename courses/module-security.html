1. Concepts Fondamentaux

La sécurité informatique repose sur trois piliers fondamentaux, regroupés sous l'acronyme CIA (ou DIC en français).

Pilier Définition Exemple de menace
Confidentialité L'information n'est accessible qu'aux personnes autorisées Fuite de données, écoute réseau
Intégrité L'information n'est pas altérée sans autorisation Modification de fichiers, injection SQL
Disponibilité Les services sont accessibles quand nécessaire Attaque DDoS, ransomware

A. Principe du Moindre Privilège

Chaque utilisateur, service ou processus ne doit avoir que les droits strictement nécessaires à son activité. C'est la règle n°1 du hardening.

  • Ne jamais travailler en root / Administrator au quotidien.
  • Créer des comptes de service dédiés avec des droits limités.
  • Désactiver les comptes inutilisés (invité, administrateur local par défaut).

B. Défense en Profondeur

Multiplier les couches de sécurité : si une couche tombe, la suivante résiste. Pare-feu périmétrique → Segmentation réseau → Durcissement OS → Antivirus → Journalisation.

Référentiel CIS Benchmark : Le Centre pour la Sécurité Internet publie des guides de configuration pour chaque OS (Windows Server, Linux, Cisco...). C'est la référence utilisée en entreprise pour auditer le niveau de durcissement.

2. Hardening Windows Server & Active Directory

Sécuriser un Active Directory est un projet à part entière. Voici les axes prioritaires pour un technicien TSSR.

A. Politique de Mots de Passe (Fine-Grained Password Policy)

Paramètre Valeur recommandée Pourquoi
Longueur minimale 12 caractères Résistance aux attaques brute-force
Complexité Activée Majuscule + chiffre + symbole obligatoires
Durée max 90 jours Limite la durée d'exposition en cas de fuite
Historique 24 mots de passe Empêche la réutilisation
Verrouillage 5 tentatives / 30 min Bloque les attaques par dictionnaire

B. GPO de Durcissement — Les incontournables

Chemins GPO critiques (Computer Configuration)
# Désactiver le compte Administrateur local intégré Computer Config > Windows Settings > Security Settings > Local Policies > Security Options > "Accounts: Administrator account status" → Disabled # Renommer le compte Administrateur > "Accounts: Rename administrator account" → ex: "sysadmin_corp" # Interdire les connexions anonymes (Null Sessions) > "Network access: Do not allow anonymous enumeration of SAM accounts" → Enabled # Forcer le verrouillage de session (écran de veille) User Config > Admin Templates > Control Panel > Personalization > "Password protect the screen saver" → Enabled > "Screen saver timeout" → 600 secondes (10 min) # Désactiver les périphériques amovibles (USB) Computer Config > Admin Templates > System > Removable Storage Access > "All Removable Storage classes: Deny all access" → Enabled

C. Sécurisation des comptes à privilèges

  • Tier Model (Microsoft) : Séparer les comptes admin en 3 niveaux — Tier 0 (DC), Tier 1 (Serveurs), Tier 2 (Postes). Un admin Tier 2 ne peut pas administrer un DC.
  • Protected Users : Groupe AD spécial qui empêche la mise en cache des credentials et force Kerberos.
  • LAPS (Local Admin Password Solution) : Génère un mot de passe administrateur local unique et aléatoire pour chaque poste, stocké dans l'AD.

Piège examen : Le compte KRBTGT est le compte de service Kerberos. Si un attaquant le compromet, il peut créer des Golden Tickets — des tickets Kerberos valables 10 ans donnant accès à tout l'AD. Il faut réinitialiser son mot de passe deux fois (pour invalider tous les tickets existants).

D. Windows Defender & Antivirus

PowerShell — Windows Defender
# Vérifier l'état de Windows Defender Get-MpComputerStatus | Select-Object AMRunningMode, RealTimeProtectionEnabled # Lancer un scan rapide Start-MpScan -ScanType QuickScan # Mettre à jour les définitions Update-MpSignature # Voir les menaces détectées Get-MpThreatDetection

3. Hardening Linux (Debian / RHEL)

Un serveur Linux fraîchement installé est loin d'être sécurisé par défaut. Voici la checklist de durcissement post-installation.

A. Checklist post-installation

1 — Mises à jour & paquets inutiles
# Mettre à jour IMMÉDIATEMENT après installation apt update && apt upgrade -y # Lister les paquets installés dpkg --list # Supprimer les services inutiles (ex: telnet, rsh, ftp) apt purge telnet rsh-client ftp -y # Vérifier les services actifs au démarrage systemctl list-unit-files --type=service --state=enabled
2 — Sécuriser SSH (/etc/ssh/sshd_config)
PermitRootLogin no # Interdire root en SSH PasswordAuthentication no # Clés uniquement Port 2222 # Changer le port (anti-scan) MaxAuthTries 3 # Limiter les tentatives ClientAliveInterval 300 # Timeout session inactive (5 min) AllowUsers romain # Whitelist des users autorisés Protocol 2 # Forcer SSHv2 uniquement # Appliquer les changements systemctl reload sshd
3 — Fail2Ban (bloquer les brute-force)
# Installer apt install fail2ban -y # Créer la config locale (ne jamais modifier jail.conf directement) cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local # Exemple de config SSH dans jail.local [sshd] enabled = true port = 2222 maxretry = 3 bantime = 3600 # Banni 1 heure findtime = 600 # Fenêtre de détection 10 min # Voir les IPs bannies fail2ban-client status sshd

B. Permissions et SUID dangereux

Audit des droits sensibles
# Trouver tous les fichiers SUID (à auditer régulièrement) find / -perm -4000 -type f 2>/dev/null # Trouver les fichiers sans propriétaire (orphelins — suspect) find / -nouser -o -nogroup 2>/dev/null # Trouver les fichiers world-writable (écriture pour tout le monde) find / -perm -0002 -type f 2>/dev/null | grep -v /proc # Vérifier les fichiers de config critiques ls -la /etc/passwd /etc/shadow /etc/sudoers # /etc/shadow doit être : -rw-r----- root shadow

C. Sudo — Principe du moindre privilège

/etc/sudoers — Exemples de configuration
# Toujours éditer avec visudo (vérifie la syntaxe) visudo # Autoriser romain à redémarrer Apache uniquement romain ALL=(ALL) /usr/bin/systemctl restart apache2 # Autoriser le groupe "admins" sans mot de passe (avec précaution) %admins ALL=(ALL) NOPASSWD: ALL # Voir ce qu'un utilisateur peut faire sudo -l -U romain

Danger : Une ligne romain ALL=(ALL) NOPASSWD: ALL dans sudoers donne les pleins pouvoirs sans mot de passe. À n'utiliser que pour des comptes de service très spécifiques, jamais pour un humain.

4. Pare-feu & Filtrage réseau

A. iptables / nftables (Linux)

Le pare-feu natif Linux. Les règles sont lues de haut en bas — la première qui correspond s'applique.

iptables — Règles essentielles
# Voir les règles actuelles iptables -L -n -v # Politique par défaut : tout bloquer en entrée iptables -P INPUT DROP iptables -P FORWARD DROP iptables -P OUTPUT ACCEPT # Autoriser les connexions établies (ne pas casser les sessions actives) iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT # Autoriser SSH (port custom 2222) iptables -A INPUT -p tcp --dport 2222 -j ACCEPT # Autoriser HTTP/HTTPS iptables -A INPUT -p tcp --dport 80 -j ACCEPT iptables -A INPUT -p tcp --dport 443 -j ACCEPT # Autoriser le loopback (obligatoire) iptables -A INPUT -i lo -j ACCEPT # Sauvegarder les règles (Debian) iptables-save > /etc/iptables/rules.v4

B. UFW — Interface simplifiée (Ubuntu/Debian)

UFW — Uncomplicated Firewall
# Activer UFW ufw enable # Politique par défaut ufw default deny incoming ufw default allow outgoing # Autoriser SSH sur port custom ufw allow 2222/tcp # Autoriser depuis une IP spécifique seulement ufw allow from 192.168.1.10 to any port 22 # Voir les règles ufw status verbose

C. Pare-feu Windows (Netsh / PowerShell)

PowerShell — Windows Firewall
# Voir les règles actives Get-NetFirewallRule | Where-Object { $_.Enabled -eq 'True' } | Select-Object DisplayName, Direction, Action # Bloquer une application New-NetFirewallRule -DisplayName "Bloquer Telnet" -Direction Inbound -Protocol TCP -LocalPort 23 -Action Block # Autoriser un port entrant New-NetFirewallRule -DisplayName "Autoriser HTTPS" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow # Activer le pare-feu sur tous les profils Set-NetFirewallProfile -Profile Domain,Public,Private -Enabled True

Zones de pare-feu Windows : Domaine (réseau AD), Privé (réseau maison/bureau de confiance), Public (WiFi public — règles les plus restrictives). Bien vérifier sur quel profil s'applique une règle.

PowerShell — Requêter les logs Windows
# Voir les 20 derniers échecs de connexion (Event 4625) Get-WinEvent -LogName Security | Where-Object { $_.Id -eq 4625 } | Select-Object -First 20 TimeCreated, Message # Voir les créations de comptes (Event 4720) Get-WinEvent -LogName Security | Where-Object { $_.Id -eq 4720 } # Exporter les logs de sécurité wevtutil epl Security C:\Backup\security_logs.evtx

6. Attaques courantes à connaître

Un technicien TSSR doit connaître les vecteurs d'attaque pour mieux défendre. Pas pour attaquer, mais pour comprendre ce qu'il faut bloquer.

Attaque Mécanisme Contre-mesure
Brute Force Essayer toutes les combinaisons de mdp Fail2Ban, verrouillage de compte, MFA
Pass-the-Hash Réutiliser le hash NTLM sans connaître le mdp LAPS, Protected Users, désactiver NTLM
Golden Ticket Forger un ticket Kerberos via le hash KRBTGT Réinitialiser KRBTGT 2x, surveiller event 4769
VLAN Hopping Accéder à un VLAN non autorisé via le native VLAN Changer le native VLAN, désactiver DTP
ARP Spoofing Empoisonner la table ARP pour intercepter le trafic Dynamic ARP Inspection (DAI) sur les switchs
Ransomware Chiffrer les fichiers et demander une rançon Sauvegardes 3-2-1, segmentation réseau, MFA
Phishing Tromper un utilisateur pour voler ses credentials Sensibilisation, MFA, filtre anti-spam

Règle 3-2-1 des sauvegardes : 3 copies des données · sur 2 supports différents · dont 1 hors site (ou hors ligne). C'est la seule vraie protection contre un ransomware.

7. Cheat Sheet Sécurité

Commandes à connaître par cœur pour l'épreuve pratique.

Windows — Audit rapide post-incident
# Qui est connecté en ce moment ? query session query user # Voir les connexions réseau actives (chercher des ports suspects) netstat -ano Get-NetTCPConnection | Where-Object { $_.State -eq 'Established' } # Lister les services installés (chercher des nouveaux) Get-Service | Sort-Object Status # Lister les tâches planifiées (vecteur de persistance malware) Get-ScheduledTask | Where-Object { $_.State -ne 'Disabled' } # Voir les partages réseau ouverts net share Get-SmbShare
Linux — Audit rapide post-incident
# Qui est connecté ? who w # Connexions réseau établies (chercher des IPs inconnues) ss -antp # Processus en cours (chercher des processus suspects) ps aux --sort=-%cpu | head -20 # Fichiers modifiés dans les dernières 24h (sur tout le système) find / -mtime -1 -type f 2>/dev/null | grep -v /proc | grep -v /sys # Crontabs de tous les utilisateurs (persistance malware) for user in $(cut -f1 -d: /etc/passwd); do crontab -u $user -l 2>/dev/null; done # Ports en écoute ss -lntp
