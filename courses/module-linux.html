2. chmod — Modifier les droits

A. Les 3 valeurs à connaître par cœur

r (Lecture) = 4  ·  w (Écriture) = 2  ·  x (Exécution) = 1

On additionne : rwx = 4+2+1 = 7  ·  rw- = 4+2 = 6  ·  r-x = 4+1 = 5  ·  r-- = 4  ·  --- = 0

Le chiffre octal se compose de 3 positions : User | Group | Others
Exemple : 755 = rwx pour User, r-x pour Group, r-x pour Others

B. Tableau de référence rapide

OctalSymboliqueSignificationCas d'usage
777rwxrwxrwxTout le monde fait tout⚠️ À éviter en prod
755rwxr-xr-xOwner: tout / Others: lire+exécuterScripts, dossiers web publics
644rw-r--r--Owner: lire+écrire / Others: lireFichiers de config, pages HTML
600rw-------Owner seulement, pas d'exécutionClés SSH (~/.ssh/id_rsa)
700rwx------Owner seul, exécution incluseScripts privés
640rw-r-----Owner: rw / Group: r / Others: rienLogs applicatifs

C. Notation octale vs symbolique

chmod — exemples pratiques
# ── NOTATION OCTALE ───────────────────────────── chmod 755 script.sh # rwxr-xr-x chmod 644 index.html # rw-r--r-- chmod -R 750 /var/www/html # Récursif sur tout le dossier # ── NOTATION SYMBOLIQUE ────────────────────────── chmod u+x script.sh # Ajouter l'exécution pour le propriétaire chmod g-w fichier.txt # Retirer l'écriture au groupe chmod o= fichier.txt # Others : aucun droit chmod a+r rapport.txt # Tout le monde peut lire (a = all) chmod u=rw,g=r,o= secret.txt # Définir chaque catégorie précisément # ── VÉRIFIER après modification ────────────────── ls -l script.sh stat fichier.txt # Affichage octal + symbolique

Examen pratique : Pour les clés SSH, chmod 600 id_rsa est obligatoire — SSH refusera de fonctionner si la clé est lisible par d'autres. Pour rendre un script exécutable : chmod +x script.sh.

3. chown & chgrp — Changer le propriétaire

A. chown

chown — syntaxe et exemples
# Changer uniquement le propriétaire chown jean fichier.txt # Changer propriétaire ET groupe (syntaxe user:group) chown jean:admins fichier.txt # Changer uniquement le groupe chown :admins fichier.txt # Récursif sur tout un dossier chown -R www-data:www-data /var/www/html

B. chgrp

chgrp — changer uniquement le groupe
chgrp admins fichier.txt chgrp -R developers /opt/projet # Récursif

Règle importante : Seul root peut changer le propriétaire d'un fichier. Un user peut changer le groupe d'un fichier qu'il possède, à condition d'appartenir au groupe cible.

C. Cas pratique — Déploiement web

Scénario : site Apache avec user "romain" + Apache (www-data)
mkdir -p /var/www/monsite chown -R romain:www-data /var/www/monsite chmod -R 750 /var/www/monsite ls -la /var/www/monsite # drwxr-x--- 2 romain www-data 4096 mai 3 10:00 monsite

4. Arborescence FHS (File Hierarchy Standard)

Sous Linux, "Tout est fichier". Comprendre où ranger les choses est la base.

  • /etc : Fichiers de configuration (/etc/network/interfaces, /etc/passwd).
  • /var : Données variables (Logs dans /var/log, Site Web dans /var/www).
  • /dev : Périphériques matériels (Disques sda, terminaux tty).
  • /proc : Système de fichiers virtuel (Info Noyau, CPU, RAM). N'existe qu'en RAM.
  • /home : Dossiers personnels des utilisateurs.
  • /tmp : Fichiers temporaires (vidé au reboot, Sticky Bit actif).
  • /opt : Logiciels tiers installés manuellement.
  • /bin, /sbin : Binaires essentiels du système.
Commandes de recherche
# Trouver les fichiers modifiés il y a moins de 24h find /home -mtime -1 # Chercher "ERROR" dans tous les logs (insensible à la casse) grep -ri "error" /var/log/ # Trouver tous les fichiers avec le SUID activé (audit sécurité) find / -perm -4000 -type f 2>/dev/null

5. Droits Spéciaux : SUID, SGID, Sticky & ACL

A. Droits Spéciaux (Le piège de l'examen)

NomCodeEffet
SUID (Set User ID)u+s (4000)Exécute avec les droits du propriétaire (ex: passwd).
SGID (Set Group ID)g+s (2000)Dans un dossier : les fichiers créés héritent du groupe parent.
Sticky Bit+t (1000)Seul le propriétaire peut supprimer son fichier (utilisé sur /tmp).
Appliquer les droits spéciaux
# Sticky Bit sur un dossier partagé chmod +t /partage chmod 1777 /partage # Équivalent octal # SUID sur un binaire chmod u+s /usr/bin/monprog chmod 4755 /usr/bin/monprog # Équivalent octal

B. ACL (Access Control Lists)

Quand UGO ne suffit pas (ex: donner des droits à 2 utilisateurs spécifiques).

Gestion des ACL
# Donner rwx à l'utilisateur "jean" sur un fichier setfacl -m u:jean:rwx fichier.txt # Donner r-x au groupe "devs" setfacl -m g:devs:rx fichier.txt # Voir les ACL getfacl fichier.txt # Supprimer toutes les ACL setfacl -b fichier.txt

6. Stockage & LVM (Logical Volume Manager)

LVM permet de redimensionner des partitions à chaud. C'est indispensable en entreprise.

Hiérarchie LVM :
1. PV (Physical Volume) : Le disque dur brut (/dev/sdb).
2. VG (Volume Group) : Le "sac" de stockage global.
3. LV (Logical Volume) : La partition virtuelle qu'on formate et monte.

Création LVM Complète
# 1. Créer le Volume Physique pvcreate /dev/sdb # 2. Créer le Groupe de Volume "data_vg" vgcreate data_vg /dev/sdb # 3. Créer un Volume Logique de 10Go lvcreate -n backups_lv -L 10G data_vg # 4. Formater (EXT4) et Monter mkfs.ext4 /dev/data_vg/backups_lv mount /dev/data_vg/backups_lv /mnt/backups # 5. Rendre le montage permanent echo "/dev/data_vg/backups_lv /mnt/backups ext4 defaults 0 2" >> /etc/fstab

8. Processus & Services

A. Gestion des Processus

  • Signaux :

9. Réseau & Sécurité SSH

A. Configuration IP (Moderne)

On n'utilise plus ifconfig (obsolète), mais la suite ip.

  • Voir les IP : ip a (ou ip addr show)
  • Voir la passerelle : ip route
  • Voir les ports ouverts : ss -lntp (Remplace netstat)

B. Sécuriser SSH (/etc/ssh/sshd_config)

Avant de mettre un serveur en prod, changez ces 3 lignes :

Config SSH Sécurisée
PermitRootLogin no # Interdire root direct PasswordAuthentication no # Clés SSH uniquement Port 2222 # Changer le port par défaut (Anti-bot) systemctl reload sshd

Authentification par clé

10. Scripting Bash Automatisé

Savoir automatiser une sauvegarde est un TP classique.

backup.sh (Boucle & Condition)
#!/bin/bash DEST="/var/backups" DATE=$(date +%Y-%m-%d) USERS=("jean" "paul" "admin") if [ ! -d "$DEST" ]; then mkdir -p "$DEST" fi for USER in "${USERS[@]}"; do echo "Sauvegarde de $USER..." tar -czf "$DEST/$USER-$DATE.tar.gz" "/home/$USER" 2>/dev/null done echo "Sauvegarde terminée !"

12. Serveur DHCP — Kea

Kea est le successeur moderne de ISC DHCP Server, développé par l'ISC. Plus rapide, configurable en JSON, avec API REST intégrée. Protocole UDP, ports 67 (serveur) et 68 (client).

A. Installation

Installation Kea DHCP
# Debian/Ubuntu apt install kea -y # RHEL/Rocky (via repo ISC) dnf install isc-kea -y # Services Kea systemctl enable --now kea-dhcp4-server # IPv4 systemctl enable --now kea-dhcp6-server # IPv6 (optionnel)

B. Configuration principale

/etc/kea/kea-dhcp4.conf
{ "Dhcp4": { "interfaces-config": { "interfaces": ["eth0"] // Interface d'écoute }, "lease-database": { "type": "memfile", "persist": true, "name": "/var/lib/kea/dhcp4.leases" }, "valid-lifetime": 86400, // Bail : 24h "max-valid-lifetime": 172800, // Bail max : 48h "option-data": [ { "name": "domain-name-servers", "data": "192.168.1.1, 8.8.8.8" }, { "name": "domain-name", "data": "mondomaine.local" } ], "subnet4": [{ "subnet": "192.168.1.0/24", "pools": [{"pool": "192.168.1.100 - 192.168.1.200"}], "option-data": [ {"name": "routers", "data": "192.168.1.254"}, {"name": "broadcast-address", "data": "192.168.1.255"} ], // ── Réservation par adresse MAC ────────────── "reservations": [ { "hw-address": "aa:bb:cc:dd:ee:ff", "ip-address": "192.168.1.10", "hostname": "serveur-web" } ] }], "loggers": [{ "name": "kea-dhcp4", "output_options": [{"output": "/var/log/kea/kea-dhcp4.log"}], "severity": "INFO" }] } }

C. Vérification et surveillance

Commandes Kea
# Vérifier la syntaxe de la config kea-dhcp4 -t /etc/kea/kea-dhcp4.conf # Voir les baux actifs cat /var/lib/kea/dhcp4.leases # Logs en temps réel journalctl -u kea-dhcp4-server -f tail -f /var/log/kea/kea-dhcp4.log # Statut du service systemctl status kea-dhcp4-server # Recharger la config sans redémarrer (API REST) curl -X POST http://127.0.0.1:8000/ \ -d '{"command":"config-reload","service":["dhcp4"]}'

Piège examen : Si le serveur DHCP est sur un sous-réseau différent des clients, il faut configurer un relais DHCP sur le routeur (Helper Address). Les requêtes DHCP sont des broadcasts qui ne traversent pas les routeurs par défaut.

13. Serveur DNS — Bind9

Bind9 est le serveur DNS open-source de référence. Il peut être résolveur récursif (cache) ou serveur autoritaire (zones).

A. Installation

Installation Bind9
# Debian/Ubuntu apt install bind9 bind9utils dnsutils -y # RHEL/Rocky dnf install bind bind-utils -y systemctl enable --now bind9 # Debian systemctl enable --now named # RHEL

B. Options principales

/etc/bind/named.conf.options
options { directory "/var/cache/bind"; # Autoriser les requêtes depuis le LAN allow-query { localhost; 192.168.1.0/24; }; # Redirecteurs DNS upstream forwarders { 8.8.8.8; 1.1.1.1; }; recursion yes; allow-recursion { localhost; 192.168.1.0/24; }; dnssec-validation auto; listen-on { any; }; };

C. Déclaration des zones

/etc/bind/named.conf.local
# Zone directe (nom → IP) zone "mondomaine.local" { type master; file "/etc/bind/zones/db.mondomaine.local"; allow-update { none; }; }; # Zone inverse (IP → nom) pour 192.168.1.x zone "1.168.192.in-addr.arpa" { type master; file "/etc/bind/zones/db.192.168.1"; allow-update { none; }; };

D. Fichier de zone directe

/etc/bind/zones/db.mondomaine.local
$TTL 604800 @ IN SOA ns1.mondomaine.local. admin.mondomaine.local. ( 2024010101 ; Serial — INCRÉMENTER à chaque modif ! 3600 ; Refresh (1h) 1800 ; Retry (30min) 604800 ; Expire (1 semaine) 86400 ) ; Negative Cache TTL (1 jour) ; ── Serveurs NS et enregistrement A ────────────── @ IN NS ns1.mondomaine.local. ns1 IN A 192.168.1.1 ; ── Enregistrements A (nom → IP) ───────────────── @ IN A 192.168.1.1 serveur-web IN A 192.168.1.10 pc-alice IN A 192.168.1.100 pc-bob IN A 192.168.1.101 ; ── Alias CNAME ────────────────────────────────── www IN CNAME serveur-web.mondomaine.local. ftp IN CNAME serveur-web.mondomaine.local. ; ── Messagerie MX ──────────────────────────────── @ IN MX 10 mail.mondomaine.local. mail IN A 192.168.1.20

F. Vérification et tests

Commandes de vérification Bind9

14. Routage & NAT (iptables)

Pour transformer un serveur Linux en routeur/passerelle NAT : activer le forwarding IP puis configurer les règles iptables.

A. Activer le routage IP

Activer le forwarding IP
# Activer temporairement (perdu au reboot) echo 1 > /proc/sys/net/ipv4/ip_forward # Activer en permanence echo "net.ipv4.ip_forward = 1" >> /etc/sysctl.conf sysctl -p # Vérifier sysctl net.ipv4.ip_forward # Doit retourner : 1

B. NAT Masquerade (SNAT dynamique)

Scénario :
eth0 = interface WAN (côté Internet / box)
eth1 = interface LAN (réseau interne 10.0.0.0/24)

Configuration NAT complète
# ── Politique par défaut ──────────────────────────── iptables -P INPUT DROP iptables -P FORWARD DROP iptables -P OUTPUT ACCEPT # ── Connexions établies (ne pas casser les sessions) ─ iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT iptables -A FORWARD -m state --state ESTABLISHED,RELATED -j ACCEPT # ── Loopback obligatoire ───────────────────────────── iptables -A INPUT -i lo -j ACCEPT # ── LAN vers Internet ──────────────────────────────── iptables -A FORWARD -i eth1 -o eth0 -j ACCEPT # ── NAT : tout le LAN sort avec l'IP de eth0 ───────── iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE # ── SSH depuis l'extérieur ─────────────────────────── iptables -A INPUT -i eth0 -p tcp --dport 22 -j ACCEPT

C. DNAT — Redirection de port (Port Forwarding)

Exposer un serveur interne (10.0.0.10)
# Rediriger le port 80 entrant vers le serveur web interne iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 80 \ -j DNAT --to-destination 10.0.0.10:80 # Autoriser le forwarding vers ce serveur iptables -A FORWARD -i eth0 -o eth1 \ -d 10.0.0.10 -p tcp --dport 80 -j ACCEPT # Idem pour HTTPS iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 443 \ -j DNAT --to-destination 10.0.0.10:443

D. Persister les règles

Sauvegarder les règles iptables
# Installer iptables-persistent (Debian) apt install iptables-persistent -y netfilter-persistent save # Sauvegarde dans /etc/iptables/rules.v4 # Sauvegarder / restaurer manuellement iptables-save > /etc/iptables/rules.v4 iptables-restore < /etc/iptables/rules.v4 # Voir les règles iptables -L -n -v --line-numbers iptables -t nat -L -n -v # Table NAT

Ordre des règles : iptables lit les règles de haut en bas, la première correspondante s'applique. Utilisez -I pour insérer en haut, -A pour ajouter en bas. Supprimer une règle par numéro : iptables -D INPUT 3.

15. Serveur Web — Apache2

Apache est le serveur web le plus utilisé sur Linux. Il supporte les VirtualHosts (plusieurs sites sur un même serveur), HTTPS via Let's Encrypt, les modules et le .htaccess.

A. Installation et structure

Installation Apache2
# Debian/Ubuntu apt install apache2 -y systemctl enable --now apache2 # RHEL/Rocky dnf install httpd -y systemctl enable --now httpd # Structure des dossiers (Debian) /etc/apache2/ ├── apache2.conf # Config principale ├── ports.conf # Ports d'écoute (80, 443) ├── sites-available/ # Sites disponibles (désactivés) ├── sites-enabled/ # Sites actifs (liens symboliques) ├── mods-available/ # Modules disponibles └── mods-enabled/ # Modules actifs # Activer/désactiver un site a2ensite monsite.conf a2dissite monsite.conf # Activer/désactiver un module a2enmod rewrite ssl headers a2dismod status # Vérifier la config et redémarrer apachectl configtest systemctl reload apache2

B. VirtualHost HTTP simple

/etc/apache2/sites-available/monsite.conf
<VirtualHost *:80> ServerName monsite.local ServerAlias www.monsite.local DocumentRoot /var/www/monsite ServerAdmin admin@monsite.local # Logs spécifiques au site ErrorLog ${APACHE_LOG_DIR}/monsite_error.log CustomLog ${APACHE_LOG_DIR}/monsite_access.log combined # Options du dossier <Directory /var/www/monsite> Options -Indexes +FollowSymLinks AllowOverride All # Autoriser le .htaccess Require all granted </Directory> </VirtualHost>

C. VirtualHost HTTPS avec SSL

/etc/apache2/sites-available/monsite-ssl.conf
<VirtualHost *:443> ServerName monsite.local DocumentRoot /var/www/monsite # Activation SSL SSLEngine on SSLCertificateFile /etc/ssl/certs/monsite.crt SSLCertificateKeyFile /etc/ssl/private/monsite.key # Sécurité SSL (désactiver les vieux protocoles) SSLProtocol all -SSLv3 -TLSv1 -TLSv1.1 SSLCipherSuite HIGH:!aNULL:!MD5 ErrorLog ${APACHE_LOG_DIR}/monsite_ssl_error.log CustomLog ${APACHE_LOG_DIR}/monsite_ssl_access.log combined </VirtualHost> # Rediriger HTTP vers HTTPS <VirtualHost *:80> ServerName monsite.local Redirect permanent / https://monsite.local/ </VirtualHost>

D. Générer un certificat auto-signé (test/lab)

Certificat SSL auto-signé
# Générer le certificat et la clé (valable 365 jours) openssl req -x509 -nodes -days 365 -newkey rsa:2048 \ -keyout /etc/ssl/private/monsite.key \ -out /etc/ssl/certs/monsite.crt \ -subj "/C=FR/ST=IDF/L=Paris/O=MonOrg/CN=monsite.local" # Activer le module SSL a2enmod ssl a2ensite monsite-ssl.conf systemctl reload apache2

E. Fichier .htaccess

/var/www/monsite/.htaccess
# Activer le moteur de réécriture Options +FollowSymLinks RewriteEngine On # Rediriger toutes les requêtes vers index.php (framework PHP) RewriteCond %{REQUEST_FILENAME} !-f RewriteCond %{REQUEST_FILENAME} !-d RewriteRule ^(.*)$ index.php?url=$1 [QSA,L] # Interdire l'accès à un dossier <Directory /var/www/monsite/private> Require all denied </Directory> # Protéger par mot de passe AuthType Basic AuthName "Zone Restreinte" AuthUserFile /etc/apache2/.htpasswd Require valid-user
Commandes Apache utiles
# Créer un utilisateur .htpasswd htpasswd -c /etc/apache2/.htpasswd alice # -c = créer le fichier htpasswd /etc/apache2/.htpasswd bob # Ajouter un user # Voir les sites et modules actifs apachectl -S # Virtual hosts apache2ctl -M # Modules chargés # Logs Apache tail -f /var/log/apache2/error.log tail -f /var/log/apache2/access.log # Test de performance ab -n 1000 -c 10 http://monsite.local/ # Apache Bench

Pièges examen :
— AllowOverride All est indispensable pour que le .htaccess soit pris en compte.
— Ne pas oublier a2enmod rewrite avant d'utiliser RewriteEngine On.
— Toujours faire apachectl configtest avant de recharger pour éviter une coupure de service.

15. Samba — Partage de fichiers & Contrôleur de domaine

Samba implémente le protocole SMB/CIFS sur Linux. Il peut être serveur de fichiers autonome ou contrôleur de domaine AD complet.

A. Serveur de fichiers (Workgroup)

Installation

🎯 Mémo Examen — Le plus important à retenir

Les points qui tombent le plus souvent en épreuve pratique TSSR. À connaître par cœur.

A. Droits et permissions — Les pièges classiques

usermod -G écrase tous les groupes → toujours -aG
chmod 600 sur les clés SSH → obligatoire, SSH refuse sinon
chown seul root peut changer le propriétaire
SUID 4000 / SGID 2000 / Sticky 1000 → ex: chmod 1777 /tmp
