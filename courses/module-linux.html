1. Utilisateurs & Groupes NOUVEAU

A. Les fichiers système clés

FichierContenu
/etc/passwdListe des users : login:x:UID:GID:commentaire:home:shell
/etc/shadowMots de passe hashés (lisible que par root)
/etc/groupListe des groupes : nom:x:GID:membres
# /etc/passwd — exemple de ligne
romain:x:1001:1001:Romain Altinkaya:/home/romain:/bin/bash
#      │  │    │   └─ commentaire    └─ home       └─ shell
#      │  │    └─ GID primaire
#      │  └─ UID
#      └─ mot de passe (x = stocké dans /etc/shadow)

B. Gestion des utilisateurs

# Créer un utilisateur (avec home + shell bash)
useradd -m -s /bin/bash jean
 
# Définir / changer le mot de passe
passwd jean
 
# Modifier un utilisateur existant
usermod -aG sudo jean          # Ajouter jean au groupe sudo (sans le retirer des autres)
usermod -s /bin/sh jean        # Changer le shell
usermod -l nouveau_login jean  # Renommer le login
 
# Supprimer un utilisateur (et son home)
userdel -r jean
 
# Afficher les groupes d'un user
groups jean
id jean

C. Gestion des groupes

# Créer un groupe
groupadd admins
 
# Ajouter un user à un groupe (méthode propre)
usermod -aG admins jean
 
# Supprimer un groupe
groupdel admins
 
# Voir tous les membres d'un groupe
getent group admins
⚠️ Piège examen : usermod -G admins jean (sans le -a) écrase tous les groupes de jean et ne lui laisse que "admins". Toujours utiliser -aG pour ajouter.

D. Devenir root / changer d'identité

sudo commande          # Exécuter UNE commande en root
sudo -i                # Ouvrir un shell root complet
su - jean              # Changer de session vers l'user jean (avec son environnement)
whoami                 # Vérifier qui on est actuellement

2. chmod — Modifier les droits NOUVEAU

A. Les 3 valeurs à connaître par cœur

rLecture
4
wÉcriture
2
xExécution
1

On additionne les valeurs : rwx = 4+2+1 = 7 · rw- = 4+2 = 6 · r-x = 4+1 = 5 · r-- = 4

B. La notation octale (3 chiffres = User | Group | Others)

OctalNotation symboliqueSignificationCas d'usage typique
777rwxrwxrwxTout le monde fait tout⚠️ À éviter en prod
755rwxr-xr-xOwner: tout / Others: lire+exécuterScripts, dossiers web publics
644rw-r--r--Owner: lire+écrire / Others: lireFichiers de config, pages HTML
600rw-------Owner seulement, pas d'exécutionClés SSH (~/.ssh/id_rsa)
700rwx------Owner seul, exécution incluseScripts privés
640rw-r-----Owner: rw / Group: r / Others: rienLogs applicatifs

C. Commandes chmod

# ── Notation OCTALE ──────────────────────────────────
chmod 755 script.sh          # rwxr-xr-x
chmod 644 index.html         # rw-r--r--
chmod -R 750 /var/www/html   # Récursif sur tout le dossier
 
# ── Notation SYMBOLIQUE ───────────────────────────────
# Syntaxe : [u/g/o/a] [+/-/=] [r/w/x]
chmod u+x script.sh          # Ajouter l'exécution pour le propriétaire
chmod g-w fichier.txt        # Retirer l'écriture au groupe
chmod o= fichier.txt         # Others : aucun droit (vide)
chmod a+r rapport.txt        # Tout le monde peut lire (a = all)
chmod u=rw,g=r,o= secret.txt # Définir précisément chaque catégorie
💡 Mémo examen : Pour les scripts shell, pensez toujours chmod +x (raccourci pour a+x). Pour les clés SSH : chmod 600 id_rsa — SSH refusera de fonctionner sinon !

D. Vérifier les droits après modification

ls -l script.sh
# -rwxr-xr-x 1 romain admins 512 mai 3 10:00 script.sh
#  └──┘└──┘└──┘
#  user group others
 
stat fichier.txt   # Affichage détaillé (droits en octal + symbolique)

3. chown & chgrp — Changer propriétaire NOUVEAU

A. chown

# Changer le propriétaire
chown jean fichier.txt
 
# Changer propriétaire ET groupe en une commande (syntaxe user:group)
chown jean:admins fichier.txt
 
# Changer uniquement le groupe (avec chown)
chown :admins fichier.txt
 
# Récursif sur tout un dossier
chown -R www-data:www-data /var/www/html
 
# Vérifier
ls -l fichier.txt
# -rw-r--r-- 1 jean admins 512 mai 3 10:00 fichier.txt

B. chgrp

# Changer uniquement le groupe
chgrp admins fichier.txt
chgrp -R developers /opt/projet   # Récursif
⚠️ Règle importante : Seul root peut changer le propriétaire d'un fichier. Un user peut changer le groupe d'un fichier qu'il possède, à condition d'appartenir au groupe cible.

C. Cas pratique complet — Déploiement d'un site web

# Scenario : déployer un site dans /var/www/monsite
# L'user "romain" doit pouvoir éditer, Apache (www-data) doit lire
 
# 1. Créer le dossier
mkdir -p /var/www/monsite
 
# 2. Attribuer le bon propriétaire et groupe
chown -R romain:www-data /var/www/monsite
 
# 3. Appliquer les droits
chmod -R 750 /var/www/monsite   # romain:rwx / www-data:r-x / others:---
chmod -R 640 /var/www/monsite/*.html  # Fichiers : romain:rw / www-data:r
 
# 4. Vérifier
ls -la /var/www/monsite

4. Arborescence FHS (File Hierarchy Standard)

Sous Linux, "Tout est fichier". Comprendre où ranger les choses est la base.

  • /etc : Fichiers de configuration (ex: /etc/network/interfaces, /etc/passwd).
  • /var : Données variables (Logs dans /var/log, Site Web dans /var/www).
  • /dev : Périphériques matériels (Disques sda, terminaux tty).
  • /proc : Système de fichiers virtuel (Info Noyau, CPU, RAM). N'existe qu'en RAM.
  • /home : Dossiers personnels des utilisateurs.
  • /tmp : Fichiers temporaires (vidé au reboot, Sticky Bit actif).
  • /bin, /sbin : Binaires essentiels du système.
  • /opt : Logiciels tiers installés manuellement.
# Trouver les fichiers modifiés il y a moins de 24h
find /home -mtime -1
# Chercher "ERROR" dans tous les logs (insensible à la casse)
grep -ri "error" /var/log/
# Trouver tous les fichiers avec le SUID activé (audit sécurité)
find / -perm -4000 -type f 2>/dev/null

5. Droits Spéciaux (SUID / SGID / Sticky) & ACL

A. Droits Standards — Rappel octal

User (u) / Group (g) / Others (o). Lecture (4) + Écriture (2) + Exécution (1).

B. Droits Spéciaux (Le piège de l'examen)

NomCodeEffet
SUID (Set User ID)u+s (4000)Exécute avec les droits du propriétaire (ex: passwd).
SGID (Set Group ID)g+s (2000)Dans un dossier : les fichiers créés héritent du groupe parent.
Sticky Bit+t (1000)Seul le propriétaire peut supprimer son fichier (utilisé sur /tmp).
# Appliquer un Sticky Bit sur un dossier partagé
chmod +t /partage
chmod 1777 /partage   # Équivalent octal
 
# Appliquer SUID sur un binaire
chmod u+s /usr/bin/monprog
chmod 4755 /usr/bin/monprog   # Équivalent octal

C. ACL (Access Control Lists)

Quand UGO ne suffit pas (ex: donner des droits à 2 utilisateurs spécifiques).

# Donner rwx à l'utilisateur "jean" sur un fichier
setfacl -m u:jean:rwx fichier.txt
# Donner r-x au groupe "devs"
setfacl -m g:devs:rx fichier.txt
# Voir les ACL
getfacl fichier.txt
# Supprimer les ACL
setfacl -b fichier.txt

6. Stockage & LVM (Logical Volume Manager)

LVM permet de redimensionner des partitions à chaud. C'est indispensable en entreprise.

Hiérarchie LVM :
1. PV (Physical Volume) : Le disque dur brut (/dev/sdb).
2. VG (Volume Group) : Le "sac" de stockage global.
3. LV (Logical Volume) : La partition virtuelle qu'on formate et monte.

# 1. Créer le Volume Physique
pvcreate /dev/sdb
# 2. Créer le Groupe de Volume "data_vg"
vgcreate data_vg /dev/sdb
# 3. Créer un Volume Logique de 10Go
lvcreate -n backups_lv -L 10G data_vg
# 4. Formater (EXT4) et Monter
mkfs.ext4 /dev/data_vg/backups_lv
mount /dev/data_vg/backups_lv /mnt/backups
# 5. Rendre le montage permanent (/etc/fstab)
echo "/dev/data_vg/backups_lv /mnt/backups ext4 defaults 0 2" >> /etc/fstab

7. Archives & Gestion des paquets NOUVEAU

A. tar — Archiver et compresser

Mémo des options : créer · extraire · verbeux · fichier · zgzip · jbzip2

# Créer une archive .tar.gz
tar -czf archive.tar.gz /home/romain/
 
# Extraire une archive
tar -xzf archive.tar.gz
 
# Extraire vers un dossier spécifique
tar -xzf archive.tar.gz -C /tmp/restauration/
 
# Lister le contenu sans extraire
tar -tzf archive.tar.gz
 
# Archive bzip2 (meilleure compression, plus lent)
tar -cjf archive.tar.bz2 /opt/projet/

B. apt — Gestion des paquets (Debian/Ubuntu)

# Mettre à jour la liste des paquets
apt update
 
# Mettre à jour tous les paquets installés
apt upgrade
 
# Installer un paquet
apt install vim htop net-tools
 
# Supprimer un paquet (garder la config)
apt remove vim
 
# Supprimer paquet + fichiers de config
apt purge vim
 
# Rechercher un paquet
apt search nom_paquet
 
# Infos sur un paquet
apt show vim
 
# Nettoyer le cache de téléchargement
apt autoremove && apt clean
💡 Examen pratique : Toujours faire apt update avant apt install sinon les dépendances peuvent échouer.

8. Processus & Services

A. Gestion des Processus

# Lister les processus
ps aux                     # Tous les processus
ps aux | grep apache2      # Filtrer
top                        # Vue dynamique
htop                       # Vue dynamique (plus lisible, à installer)
 
# Tuer un processus
kill 1234                  # SIGTERM (propre) — remplacer 1234 par le PID
kill -9 1234               # SIGKILL (forcé)
killall apache2            # Tuer par nom
  • PID : Process ID (Identifiant unique).
  • SIGTERM (15) : "Ferme-toi proprement s'il te plaît".
  • SIGKILL (9) : "Meurs tout de suite" (perte de données possible).

B. Systemd (Systemctl)

# Démarrer / arrêter / redémarrer un service
systemctl start apache2
systemctl stop apache2
systemctl restart apache2
systemctl reload apache2    # Recharge la config sans couper le service
 
# Activer / désactiver au démarrage
systemctl enable apache2
systemctl disable apache2
 
# Statut d'un service
systemctl status apache2
 
# Analyser pourquoi un service a planté (CRUCIAL)
journalctl -xe
journalctl -u apache2 -f   # Logs en direct

9. Réseau & Sécurité SSH

A. Configuration IP (Moderne)

On n'utilise plus ifconfig (obsolète), mais la suite ip.

ip a                        # Voir les IP (ip addr show)
ip route                    # Voir la passerelle
ss -lntp                    # Voir les ports ouverts (remplace netstat)
ping -c 4 8.8.8.8           # Test connectivité
traceroute 8.8.8.8          # Tracer le chemin réseau
nslookup google.com         # Test DNS
dig google.com              # Test DNS détaillé

B. Sécuriser SSH (/etc/ssh/sshd_config)

Avant de mettre un serveur en prod, changez ces 3 lignes :

PermitRootLogin no          # Interdire root direct
PasswordAuthentication no  # Clés SSH uniquement
Port 2222                   # Changer le port par défaut (Anti-bot)
 
# Après modification, recharger SSH
systemctl reload sshd

C. Générer et déployer une clé SSH

# Sur le client : générer la paire de clés
ssh-keygen -t ed25519 -C "romain@monpc"
 
# Copier la clé publique sur le serveur
ssh-copy-id -i ~/.ssh/id_ed25519.pub user@serveur
 
# Se connecter
ssh -i ~/.ssh/id_ed25519 user@serveur -p 2222

10. Scripting Bash Automatisé

#!/bin/bash
# Variables
DEST="/var/backups"
DATE=$(date +%Y-%m-%d)
USERS=("jean" "paul" "admin")
 
# Vérifier si le dossier existe
if [ ! -d "$DEST" ]; then
  mkdir -p "$DEST"
fi
 
# Boucle sur les utilisateurs
for USER in "${USERS[@]}"; do
  echo "Sauvegarde de $USER..."
  tar -czf "$DEST/$USER-$DATE.tar.gz" "/home/$USER" 2>/dev/null
done
 
echo "Sauvegarde terminée !"
