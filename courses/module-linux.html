B. Gestion des utilisateurs

useradd / usermod / userdel
# Créer un utilisateur (avec home + shell bash) useradd -m -s /bin/bash jean # Définir / changer le mot de passe passwd jean # Ajouter jean au groupe sudo (sans le retirer des autres) usermod -aG sudo jean # Changer le shell usermod -s /bin/sh jean # Supprimer un utilisateur ET son dossier home userdel -r jean # Afficher les groupes et l'UID/GID d'un user groups jean id jean

Piège examen : usermod -G admins jean (sans -a) écrase tous les groupes de jean. Toujours utiliser -aG pour ajouter sans supprimer les groupes existants.

2. chmod — Modifier les droits

A. Les 3 valeurs à connaître par cœur

r (Lecture) = 4  ·  w (Écriture) = 2  ·  x (Exécution) = 1

On additionne : rwx = 4+2+1 = 7  ·  rw- = 4+2 = 6  ·  r-x = 4+1 = 5  ·  r-- = 4  ·  --- = 0

Le chiffre octal se compose de 3 positions : User | Group | Others
Exemple : 755 = rwx pour User, r-x pour Group, r-x pour Others

B. Tableau de référence rapide

OctalSymboliqueSignificationCas d'usage
777rwxrwxrwxTout le monde fait tout⚠️ À éviter en prod
755rwxr-xr-xOwner: tout / Others: lire+exécuterScripts, dossiers web publics
644rw-r--r--Owner: lire+écrire / Others: lireFichiers de config, pages HTML
600rw-------Owner seulement, pas d'exécutionClés SSH (~/.ssh/id_rsa)
700rwx------Owner seul, exécution incluseScripts privés
640rw-r-----Owner: rw / Group: r / Others: rienLogs applicatifs

C. Notation octale vs symbolique

chmod — exemples pratiques
# ── NOTATION OCTALE ───────────────────────────── chmod 755 script.sh # rwxr-xr-x chmod 644 index.html # rw-r--r-- chmod -R 750 /var/www/html # Récursif sur tout le dossier # ── NOTATION SYMBOLIQUE ────────────────────────── # Syntaxe : [u/g/o/a] [+/-/=] [r/w/x] chmod u+x script.sh # Ajouter l'exécution pour le propriétaire chmod g-w fichier.txt # Retirer l'écriture au groupe chmod o= fichier.txt # Others : aucun droit chmod a+r rapport.txt # Tout le monde peut lire (a = all) chmod u=rw,g=r,o= secret.txt # Définir chaque catégorie précisément # ── VÉRIFIER après modification ────────────────── ls -l script.sh # -rwxr-xr-x 1 romain admins 512 mai 3 10:00 script.sh stat fichier.txt # Affichage octal + symbolique

Examen pratique : Pour les clés SSH, chmod 600 id_rsa est obligatoire — SSH refusera de fonctionner si la clé est lisible par d'autres. Pour rendre un script exécutable : chmod +x script.sh.

3. chown & chgrp — Changer le propriétaire

A. chown

chown — syntaxe et exemples
# Changer uniquement le propriétaire chown jean fichier.txt # Changer propriétaire ET groupe en une commande (syntaxe user:group) chown jean:admins fichier.txt # Changer uniquement le groupe (avec chown) chown :admins fichier.txt # Récursif sur tout un dossier (très courant en prod) chown -R www-data:www-data /var/www/html # Vérifier ls -l fichier.txt # -rw-r--r-- 1 jean admins 512 mai 3 10:00 fichier.txt

B. chgrp

chgrp — changer uniquement le groupe
chgrp admins fichier.txt chgrp -R developers /opt/projet # Récursif

Règle importante : Seul root peut changer le propriétaire d'un fichier. Un user peut changer le groupe d'un fichier qu'il possède, à condition d'appartenir au groupe cible.

C. Cas pratique complet — Déploiement web

Scénario : site Apache avec user "romain" + Apache (www-data)
# 1. Créer le dossier du site mkdir -p /var/www/monsite # 2. Attribuer : romain propriétaire, www-data groupe chown -R romain:www-data /var/www/monsite # 3. romain peut tout faire, Apache peut lire/naviguer, Others : rien chmod -R 750 /var/www/monsite # 4. Vérifier ls -la /var/www/monsite # drwxr-x--- 2 romain www-data 4096 mai 3 10:00 monsite

4. Arborescence FHS (File Hierarchy Standard)

Sous Linux, "Tout est fichier". Comprendre où ranger les choses est la base.

  • /etc : Fichiers de configuration (ex: /etc/network/interfaces, /etc/passwd).
  • /var : Données variables (Logs dans /var/log, Site Web dans /var/www).
  • /dev : Périphériques matériels (Disques sda, terminaux tty).
  • /proc : Système de fichiers virtuel (Info Noyau, CPU, RAM). N'existe qu'en RAM.
  • /home : Dossiers personnels des utilisateurs.
  • /tmp : Fichiers temporaires (vidé au reboot, Sticky Bit actif).
  • /opt : Logiciels tiers installés manuellement.
  • /bin, /sbin : Binaires essentiels du système.
Commandes de recherche
# Trouver les fichiers modifiés il y a moins de 24h find /home -mtime -1 # Chercher "ERROR" dans tous les logs (insensible à la casse) grep -ri "error" /var/log/ # Trouver tous les fichiers avec le SUID activé (audit sécurité) find / -perm -4000 -type f 2>/dev/null

5. Droits Spéciaux : SUID, SGID, Sticky & ACL

A. Droits Spéciaux (Le piège de l'examen)

NomCodeEffet
SUID (Set User ID) u+s (4000) Exécute avec les droits du propriétaire (ex: passwd).
SGID (Set Group ID) g+s (2000) Dans un dossier : les fichiers créés héritent du groupe parent (Collaboratif).
Sticky Bit +t (1000) Seul le propriétaire peut supprimer son fichier (utilisé sur /tmp).
Appliquer les droits spéciaux
# Sticky Bit sur un dossier partagé chmod +t /partage chmod 1777 /partage # Équivalent octal # SUID sur un binaire chmod u+s /usr/bin/monprog chmod 4755 /usr/bin/monprog # Équivalent octal

B. ACL (Access Control Lists)

Quand UGO ne suffit pas (ex: donner des droits à 2 utilisateurs spécifiques).

Gestion des ACL
# Donner rwx à l'utilisateur "jean" sur un fichier setfacl -m u:jean:rwx fichier.txt # Donner r-x au groupe "devs" setfacl -m g:devs:rx fichier.txt # Voir les ACL getfacl fichier.txt # Supprimer toutes les ACL setfacl -b fichier.txt

6. Stockage & LVM (Logical Volume Manager)

LVM permet de redimensionner des partitions à chaud. C'est indispensable en entreprise.

Hiérarchie LVM :
1. PV (Physical Volume) : Le disque dur brut (/dev/sdb).
2. VG (Volume Group) : Le "sac" de stockage global.
3. LV (Logical Volume) : La partition virtuelle qu'on formate et monte.

Création LVM Complète
# 1. Créer le Volume Physique pvcreate /dev/sdb # 2. Créer le Groupe de Volume "data_vg" vgcreate data_vg /dev/sdb # 3. Créer un Volume Logique de 10Go lvcreate -n backups_lv -L 10G data_vg # 4. Formater (EXT4) et Monter mkfs.ext4 /dev/data_vg/backups_lv mount /dev/data_vg/backups_lv /mnt/backups # 5. Rendre le montage permanent echo "/dev/data_vg/backups_lv /mnt/backups ext4 defaults 0 2" >> /etc/fstab

7. Archives & Gestion des paquets

A. tar — Archiver et compresser

Mémo des options tar :  créer  ·  extraire  ·  verbeux  ·  fichier  ·  z=gzip  ·  j=bzip2

tar — exemples pratiques
# Créer une archive .tar.gz tar -czf archive.tar.gz /home/romain/ # Extraire une archive tar -xzf archive.tar.gz # Extraire vers un dossier spécifique tar -xzf archive.tar.gz -C /tmp/restauration/ # Lister le contenu sans extraire tar -tzf archive.tar.gz # Archive bzip2 (meilleure compression, plus lent) tar -cjf archive.tar.bz2 /opt/projet/

B. apt — Gestion des paquets (Debian/Ubuntu)

apt — commandes essentielles
# Mettre à jour la liste des paquets (toujours avant install) apt update # Mettre à jour tous les paquets installés apt upgrade # Installer un ou plusieurs paquets apt install vim htop net-tools # Supprimer (garder la config) apt remove vim # Supprimer paquet + fichiers de config apt purge vim # Rechercher un paquet apt search nom_paquet # Infos sur un paquet apt show vim # Nettoyer le cache apt autoremove && apt clean

Examen pratique : Toujours faire apt update avant apt install — sinon les dépendances peuvent échouer ou vous installez une version obsolète.

8. Processus & Services

A. Gestion des Processus

  • PID : Process ID (Identifiant unique).
  • Signaux :
    • SIGTERM (15) : "Ferme-toi proprement s'il te plaît" (Défaut).
    • SIGKILL (9) : "Meurs tout de suite" (Arrêt forcé, perte de données possible).
Gestion des processus
ps aux # Lister tous les processus ps aux | grep apache2 # Filtrer par nom top # Vue dynamique htop # Vue dynamique (plus lisible) kill 1234 # SIGTERM (propre) kill -9 1234 # SIGKILL (forcé) killall apache2 # Tuer par nom

B. Systemd (Systemctl)

Le gestionnaire de démarrage moderne (PID 1).

Gestion Services & Logs
# Démarrer / arrêter / redémarrer systemctl start apache2 systemctl stop apache2 systemctl restart apache2 systemctl reload apache2 # Recharge la config sans couper le service # Activer / désactiver au démarrage systemctl enable apache2 systemctl disable apache2 # Statut d'un service systemctl status apache2 # Analyser pourquoi un service a planté (CRUCIAL) journalctl -xe journalctl -u apache2 -f # Logs en direct

9. Réseau & Sécurité SSH

A. Configuration IP (Moderne)

On n'utilise plus ifconfig (obsolète), mais la suite ip.

  • Voir les IP : ip a (ou ip addr show)
  • Voir la passerelle : ip route
  • Voir les ports ouverts : ss -lntp (Remplace netstat)

B. Sécuriser SSH (/etc/ssh/sshd_config)

Avant de mettre un serveur en prod, changez ces 3 lignes :

Config SSH Sécurisée
PermitRootLogin no # Interdire root direct PasswordAuthentication no # Clés SSH uniquement Port 2222 # Changer le port par défaut (Anti-bot) # Après modification, recharger SSH systemctl reload sshd

C. Générer et déployer une clé SSH

Authentification par clé
# Sur le client : générer la paire de clés ssh-keygen -t ed25519 -C "romain@monpc" # Copier la clé publique sur le serveur ssh-copy-id -i ~/.ssh/id_ed25519.pub user@serveur # Se connecter avec la clé ssh -i ~/.ssh/id_ed25519 user@serveur -p 2222 # Droits obligatoires sur la clé privée ! chmod 600 ~/.ssh/id_ed25519

10. Scripting Bash Automatisé

Savoir automatiser une sauvegarde est un TP classique.

backup.sh (Boucle & Condition)
#!/bin/bash # Variables DEST="/var/backups" DATE=$(date +%Y-%m-%d) USERS=("jean" "paul" "admin") # Vérifier si le dossier existe if [ ! -d "$DEST" ]; then mkdir -p "$DEST" fi # Boucle sur les utilisateurs for USER in "${USERS[@]}"; do echo "Sauvegarde de $USER..." tar -czf "$DEST/$USER-$DATE.tar.gz" "/home/$USER" 2>/dev/null done echo "Sauvegarde terminée !"

-d dossierLe dossier existe

-n "$var"La variable n'est pas vide
$? -eq 0La dernière commande a réussi (code retour = 0)
