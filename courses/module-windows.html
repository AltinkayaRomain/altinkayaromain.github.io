1. Architecture ADDS & FSMO

L'Active Directory est une base de données (NTDS.DIT) accessible via le protocole LDAP (389). Il faut maîtriser la structure logique et physique.

A. Structure Logique

  • Forêt : L'instance la plus haute. Frontière de sécurité ultime.
  • Arbre : Ensemble de domaines partageant un espace de nom (ex: corp.local et dev.corp.local).
  • Domaine : Frontière d'administration. Les admins du domaine A n'ont pas de droits sur le domaine B par défaut.
  • OU (Unité d'Organisation) : Le SEUL conteneur sur lequel on peut lier une GPO et déléguer l'administration.

B. Les 5 Rôles FSMO

Rôle Portée Fonction Critique
Contrôleur de SchémaForêt (1 seul)Modifie la structure de la base AD (ex: ajout attribut Exchange).
Maître d'attribution de nomsForêt (1 seul)Gère l'ajout/suppression de domaines dans la forêt.
PDC EmulatorDomaineLe plus critique : Source NTP, verrouillage mdp, compatibilité anciens clients.
RID MasterDomaineDistribue les blocs d'ID (SID) pour créer des objets AD.
Infrastructure MasterDomaineGère les références d'objets inter-domaines.
PowerShell — Trouver les maîtres FSMO
Get-ADDomain | Select-Object PDCEmulator, RIDMaster, InfrastructureMaster Get-ADForest | Select-Object SchemaMaster, NamingMaster # Depuis CMD netdom query fsmo

C. Sites & Services AD

Les sites AD représentent la topologie physique du réseau (liens WAN). Ils optimisent la réplication et l'authentification des clients.

  • Site : Ensemble de sous-réseaux IP bien connectés (LAN).
  • Site Link : Connexion entre deux sites (définit la fréquence et le coût de réplication).
  • KCC (Knowledge Consistency Checker) : Crée automatiquement la topologie de réplication entre les DC.
PowerShell — Réplication AD
# Forcer la réplication immédiate repadmin /syncall /AdeP # Voir l'état de la réplication repadmin /showrepl # Diagnostiquer les erreurs de réplication dcdiag /test:replications

2. Service DNS (Domain Name System)

90% des pannes AD viennent du DNS. Le DNS traduit les noms en IP, mais localise surtout les services (LDAP, Kerberos) via les enregistrements SRV.

A. Types de Zones

  • Zone Principale : Copie en lecture/écriture. Source de vérité pour la zone.
  • Zone Secondaire : Copie en lecture seule reçue du serveur principal (redondance).
  • Zone Stub : Contient uniquement les enregistrements NS d'un autre domaine (délégation).
  • Zone intégrée AD : Stockée dans l'AD, réplication multi-maître sécurisée entre tous les DC. Recommandée en environnement AD.

B. Types d'enregistrements critiques

TypeRôleExemple
ANom → IPv4dc1 → 192.168.1.1
PTRIP → Nom (zone inverse)1.1.168.192.in-addr.arpa → dc1.mondomaine.local
SRVLocalisation de services AD_ldap._tcp → dc1:389
CNAMEAliaswww → serveur-web.mondomaine.local
MXServeur mailmondomaine.local → mail.mondomaine.local (priorité 10)

Question Examen : "Comment un PC trouve son contrôleur de domaine ?"
Réponse : Via les enregistrements SRV dans le dossier _msdcs du DNS. C'est pourquoi le DNS doit absolument fonctionner avant l'AD.

C. Forwarders vs Root Hints

  • Redirecteurs (Forwarders) : Si le serveur ne connaît pas la réponse, il interroge un DNS externe (8.8.8.8, FAI). Méthode recommandée.
  • Racine (Root Hints) : Interroge directement les 13 serveurs racines mondiaux. Plus lent.

D. Dépannage DNS

PowerShell & CMD — Diagnostic DNS

3. DHCP & Processus DORA

Distribution automatique des paramètres réseau. Protocole UDP, ports 67 (serveur) et 68 (client).

A. Le Processus DORA

  1. Discover (Broadcast) : Le client cherche un serveur DHCP.
  2. Offer (Broadcast/Unicast) : Le serveur propose une IP disponible.
  3. Request (Broadcast) : Le client accepte l'offre.
  4. Acknowledge (Unicast) : Le serveur confirme et enregistre le bail.

B. Options DHCP importantes

OptionCodeDescription
Routeur003Passerelle par défaut
Serveurs DNS006Adresses des serveurs DNS
Nom de domaine015Suffixe DNS (ex: mondomaine.local)
Serveur WINS044Résolution NetBIOS (legacy)
Serveur PXE (WDS)066/067Boot réseau pour WDS/MDT

C. DHCP Failover (Haute disponibilité)

Le failover DHCP permet à deux serveurs DHCP de se partager une étendue pour assurer la continuité en cas de panne.

  • Mode Hot Standby : Un serveur actif, un en veille (5% des baux réservés au standby).
  • Mode Load Balance : Les deux serveurs se partagent les baux (50/50 par défaut).
PowerShell — Administration DHCP
# Installer le rôle DHCP Install-WindowsFeature -Name DHCP -IncludeManagementTools # Autoriser le serveur DHCP dans AD Add-DhcpServerInDC -DnsName "dhcp01.mondomaine.local" -IPAddress 192.168.1.2 # Créer une étendue (scope) Add-DhcpServerv4Scope -Name "LAN Principal" ` -StartRange 192.168.1.100 ` -EndRange 192.168.1.200 ` -SubnetMask 255.255.255.0 ` -State Active # Configurer les options de l'étendue Set-DhcpServerv4OptionValue -ScopeId 192.168.1.0 ` -Router 192.168.1.254 ` -DnsServer 192.168.1.1 ` -DnsDomain "mondomaine.local" # Ajouter une réservation Add-DhcpServerv4Reservation -ScopeId 192.168.1.0 ` -IPAddress 192.168.1.10 ` -ClientId "AA-BB-CC-DD-EE-FF" ` -Description "Serveur Web" # Voir les baux actifs Get-DhcpServerv4Lease -ScopeId 192.168.1.0 # Configurer le failover Add-DhcpServerv4Failover -Name "DHCP-Failover" ` -PartnerServer "dhcp02.mondomaine.local" ` -ScopeId 192.168.1.0 ` -Mode LoadBalance ` -LoadBalancePercent 50

Piège examen : Un serveur DHCP doit être autorisé dans l'AD avant de pouvoir distribuer des IP sur un domaine. Sans autorisation, il reste silencieux. Commande : Add-DhcpServerInDC.

4. GPO (Group Policy Objects)

A. Ordre d'application : L.S.D.O.U.

La dernière GPO appliquée écrase les précédentes sur les mêmes paramètres.

  1. Local (Le PC lui-même — priorité la plus basse)
  2. Site (Géographique, défini dans AD Sites & Services)
  3. Domaine
  4. OU (Unités d'Organisation — parents puis enfants — priorité la plus haute)

Exceptions :
— Enforced (Appliquer) : La GPO gagne toujours, même si une OU enfant bloque l'héritage.
— Block Inheritance : L'OU ignore les GPO des niveaux supérieurs (sauf si Enforced).
— Loopback Processing : Applique les GPO de l'ordinateur à l'utilisateur connecté dessus (utile pour les salles info).

B. Ciblage Avancé

  • Filtre de Sécurité : Définit QUI applique la GPO. Par défaut : Authenticated Users. Peut être restreint à un groupe.
  • Filtre WMI : Condition technique (ex: appliquer uniquement si OS = Windows 11 Pro).
  • Item-Level Targeting (GPP) : Ciblage très fin sur des préférences (ex: lecteur réseau Z: uniquement pour le groupe "Compta").

C. GPO Preferences vs GPO Settings

CaractéristiqueSettings (Stratégies)Preferences (Préférences)
CaractèreObligatoire (l'utilisateur ne peut pas changer)Suggéré (l'utilisateur peut modifier)
ExemplesPolitique de mdp, firewall, fond d'écran forcéLecteurs réseau, imprimantes, raccourcis
Item-Level TargetingNon disponibleDisponible

5. Serveur de Fichiers (NTFS / DFS)

A. NTFS vs Partage réseau — La Règle d'Or

Quand on accède à un dossier via le réseau, deux niveaux de droits s'appliquent simultanément :

  • Droits de Partage : La porte d'entrée réseau. Souvent : Tout le monde = Modifier.
  • Droits NTFS (Sécurité) : La vraie sécurité fine. C'est ici qu'on gère les groupes et l'héritage.

Règle absolue : C'est toujours la permission la plus RESTRICTIVE qui s'applique.

B. Permissions NTFS — Les niveaux

PermissionFichiersDossiers
LectureLire le contenuLister les fichiers
Lecture & ExécutionLire + exécuterTraverser le dossier
ÉcritureModifier le contenuCréer des fichiers/dossiers
ModificationLire + Écrire + SupprimerLire + Écrire + Supprimer
Contrôle TotalTout + changer les droitsTout + changer les droits

Bonne pratique AGDLP :
Account (utilisateurs) → Global group → Domain Local group → Permission
On ajoute les utilisateurs dans des groupes globaux, qu'on met dans des groupes locaux de domaine, auxquels on attribue les permissions NTFS.

C. FSRM (File Server Resource Manager)

PowerShell — FSRM
# Installer FSRM Install-WindowsFeature -Name FS-Resource-Manager -IncludeManagementTools # Créer un quota de 1 Go sur un dossier New-FsrmQuota -Path "D:\Partages\RH" -Size 1GB # Créer un filtre de fichiers (interdire .mp3 et .avi) New-FsrmFileGroup -Name "Multimedia" -IncludePattern @("*.mp3","*.mp4","*.avi","*.mkv") New-FsrmFileScreen -Path "D:\Partages" -Template "Block Audio and Video Files"

D. DFS (Distributed File System)

  • DFS Namespace : Point d'entrée unique \\corp.local\Public masquant les vrais serveurs. Transparence pour les utilisateurs.
  • DFS Replication (DFSR) : Synchronise les dossiers entre serveurs pour la haute disponibilité et la géo-redondance.
PowerShell — DFS
# Installer DFS Install-WindowsFeature -Name FS-DFS-Namespace, FS-DFS-Replication -IncludeManagementTools # Créer un namespace New-DfsnRoot -TargetPath "\\SRV01\Public" -Type DomainV2 -Path "\\mondomaine.local\Public" # Ajouter un lien DFS New-DfsnFolder -Path "\\mondomaine.local\Public\RH" -TargetPath "\\SRV01\RH" # Voir l'état de la réplication DFSR Get-DfsrMembership -GroupName * | Select-Object GroupName, ComputerName, State

6. RDS — Remote Desktop Services

RDS permet aux utilisateurs d'accéder à des applications ou bureaux Windows à distance, centralisés sur un serveur. Utilisé pour les clients légers et le télétravail.

A. Composants RDS

RôleDescription
RD Session Host (RDSH)Héberge les sessions utilisateurs. Le serveur principal.
RD Connection BrokerRépartit la charge entre plusieurs RDSH et gère la reconnexion.
RD Web AccessPortail web pour accéder aux applications publiées (RemoteApp).
RD GatewayPoint d'entrée sécurisé depuis Internet (HTTPS port 443).
RD LicensingGère les licences CAL RDS. Obligatoire après 120 jours.

B. Installation et configuration

PowerShell — Installation RDS
# Installer les rôles RDS Install-WindowsFeature -Name RDS-RD-Server, RDS-Connection-Broker, ` RDS-Web-Access, RDS-Licensing -IncludeManagementTools # Autoriser les connexions Bureau à distance (sur le RDSH) Set-ItemProperty -Path "HKLM:\System\CurrentControlSet\Control\Terminal Server" ` -Name "fDenyTSConnections" -Value 0 # Autoriser dans le firewall Enable-NetFirewallRule -DisplayGroup "Remote Desktop" # Ajouter des utilisateurs au groupe "Remote Desktop Users" Add-LocalGroupMember -Group "Remote Desktop Users" -Member "jean.dupont" # Voir les sessions actives Get-RDUserSession -ConnectionBroker "broker.mondomaine.local" # Déconnecter une session Disconnect-RDUser -HostServer "rdsh01.mondomaine.local" -UnifiedSessionID 3

C. RemoteApp — Publier une application

PowerShell — RemoteApp
# Publier une application RemoteApp New-RDRemoteApp -CollectionName "Collection RH" ` -DisplayName "Word 2024" ` -FilePath "C:\Program Files\Microsoft Office\root\Office16\WINWORD.EXE" ` -ConnectionBroker "broker.mondomaine.local" # Lister les RemoteApps publiées Get-RDRemoteApp -ConnectionBroker "broker.mondomaine.local"

Licence RDS : Sans serveur de licences RDS correctement configuré, les sessions se déconnectent après 120 jours (période de grâce). Le serveur RD Licensing doit être activé et pointé depuis les RDSH via GPO.

7. IIS — Internet Information Services

IIS est le serveur web de Microsoft intégré à Windows Server. Il héberge des sites web, applications .NET, et services web.

A. Installation

8. WDS / MDT — Déploiement de postes

WDS (Windows Deployment Services) et MDT (Microsoft Deployment Toolkit) permettent de déployer Windows en masse via le réseau (PXE Boot), sans DVD ni clé USB.

A. WDS — Windows Deployment Services

  • Rôle : Serveur PXE qui envoie les images Windows via le réseau.
  • Images de démarrage (Boot Image) : WinPE — démarre le PC avant l'installation.
  • Images d'installation (Install Image) : L'OS à installer (install.wim du DVD Windows).
PowerShell — Installation et configuration WDS
# Installer WDS Install-WindowsFeature -Name WDS -IncludeManagementTools # Configurer WDS (dossier de stockage des images) wdsutil /Initialize-Server /RemInst:"D:\RemoteInstall" wdsutil /Set-Server /AnswerClients:All # Ajouter une image de démarrage (WinPE) wdsutil /Add-Image /ImageFile:"D:\Sources\boot.wim" /ImageType:Boot # Ajouter une image d'installation wdsutil /Add-Image /ImageFile:"D:\Sources\install.wim" /ImageType:Install /ImageGroup:"Windows 11" # Voir les images disponibles wdsutil /Get-AllImages /Show:All

B. MDT — Microsoft Deployment Toolkit

MDT s'appuie sur WDS pour automatiser entièrement le déploiement : partitionnement, installation, drivers, applications, jonction au domaine.

  • Deployment Share : Dossier partagé contenant tout le nécessaire (OS, drivers, apps, scripts).
  • Task Sequence : Séquence d'étapes automatisées du déploiement.
  • Unattend.xml : Fichier de réponses pour automatiser l'installation Windows.
  • MDT DB : Base de données qui associe un PC (MAC ou nom) à une configuration spécifique.
Configuration DHCP pour PXE Boot
# Le DHCP doit fournir les options PXE aux clients # Option 66 (Boot Server) : adresse IP du serveur WDS # Option 67 (Boot Filename) : chemin du fichier de démarrage Set-DhcpServerv4OptionValue -OptionId 66 -Value "192.168.1.5" # IP WDS Set-DhcpServerv4OptionValue -OptionId 67 -Value "boot\x64\wdsnbp.com"

Flux de déploiement PXE :
1. Le PC démarre → BIOS/UEFI en mode PXE
2. Le DHCP donne une IP + options 66/67 (serveur WDS)
3. WDS envoie WinPE via TFTP
4. WinPE démarre et se connecte au Deployment Share MDT
5. La Task Sequence s'exécute (partitionnement, copie OS, drivers, apps, domaine)

9. Hyper-V — Virtualisation Windows

Hyper-V est l'hyperviseur de type 1 intégré à Windows Server. Il permet de créer et gérer des machines virtuelles directement sur le serveur physique.

A. Concepts clés

  • VM (Machine Virtuelle) : Serveur virtuel avec son propre OS, CPU virtuel, RAM et disque.
  • VHD/VHDX : Format de disque virtuel. VHDX supporte jusqu'à 64 To et est plus résilient.
  • Snapshot/Checkpoint : Point de restauration de la VM à un instant T.
  • Live Migration : Déplacer une VM d'un hôte à un autre sans interruption (nécessite un cluster).
  • Réplication Hyper-V : Copie asynchrone d'une VM vers un site secondaire (DR).

B. Types de switchs virtuels

TypeDescriptionUsage
ExternalConnecté au réseau physiqueVMs accessibles depuis le réseau
InternalEntre VMs + hôte Hyper-V uniquementGestion, communication hôte-VM
PrivateEntre VMs uniquement (hôte exclu)Réseau isolé entre VMs
PowerShell — Administration Hyper-V
# Installer Hyper-V Install-WindowsFeature -Name Hyper-V -IncludeManagementTools -Restart # Créer une VM New-VM -Name "SRV-TEST" ` -MemoryStartupBytes 2GB ` -Path "D:\VMs" ` -NewVHDPath "D:\VMs\SRV-TEST\SRV-TEST.vhdx" ` -NewVHDSizeBytes 60GB ` -Generation 2 # Configurer la VM Set-VMProcessor -VMName "SRV-TEST" -Count 2 Set-VMMemory -VMName "SRV-TEST" -DynamicMemoryEnabled $true -MinimumBytes 1GB -MaximumBytes 4GB # Connecter au switch réseau Connect-VMNetworkAdapter -VMName "SRV-TEST" -SwitchName "vSwitch-LAN" # Démarrer / arrêter Start-VM -Name "SRV-TEST" Stop-VM -Name "SRV-TEST" -Force # Créer un checkpoint Checkpoint-VM -Name "SRV-TEST" -SnapshotName "Avant-MAJ" # Restaurer un checkpoint Restore-VMCheckpoint -VMName "SRV-TEST" -Name "Avant-MAJ" # Lister les VMs Get-VM | Select-Object Name, State, MemoryAssigned, Uptime

🎯 Mémo Examen — Le plus important à retenir

A. Les pièges classiques

DNS d'abord : Toujours vérifier le DNS avant de déboguer l'AD. 90% des pannes AD = DNS.
DHCP autorisé : Un serveur DHCP doit être autorisé dans l'AD sinon il ne répond pas.
Règle NTFS : Permission la plus restrictive entre NTFS et partage = permission effective.
GPO Enforced : Gagne toujours sur Block Inheritance.

D. Ordre logique d'installation d'un rôle Windows

1. Install-WindowsFeature -Name NomRole -IncludeManagementTools
2. Configurer via GUI (Server Manager) ou PowerShell
3. Vérifier avec Get-WindowsFeature et les outils du rôle
4. Autoriser dans le pare-feu Windows si nécessaire
5. Tester depuis un client (Test-NetConnection, nslookup...)
6. Vérifier les Event Logs si problème (Get-EventLog)
